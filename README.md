# cc-flow-lab

## 节点齐套闸

落库前必须先过节点齐套闸。**齐不齐由服务端裁定**（`app/db.py: missing_nodes`），
节点字段空缺即缺项，**编码节点空缺也算缺项**。

### 闸门状态

| 状态 | 含义 |
|------|------|
| 待检 | 尚未核验，禁止落库 |
| 核验中 | 先手正在核验；期间不改策略、不落库 |
| 已过 | 节点齐套，可落库 |
| 待复核 | 缺项但按策略仍落库，之后列表只读 |
| 已退回 | 缺项被整批拦住，退回重抽 |

### 齐套策略（本日钉死，不许换弦）

`policy_day` 每个自然日只钉死一条记录，当天不可换另一种：

- `block` **缺项拦截**：缺项则整批拦住落库并退回重抽。
- `review` **缺项待复核**：缺项仍可落库，但改成待复核且列表只读。
  （默认策略；可用 `CC_FLOW_POLICY=block|review` 改预置值。）

首次核验/落库时自动按预置值钉死；核验还在跑时不允许改策略（`reason=verifying`）。

### 争抢核验

双方争抢同一条流的齐套核验，只有先手（`待检 → 核验中` 的 CAS 成功者）那次算过；
后手一律落败（`reason=lost`），并在该流上累加 `verify_lost`。缺项卡片展开后
同时显示缺项名与“抢检落败”字样。

### 落库门槛与路径校验

点落库时页面带上它认为生效的齐套路径 `path`；与服务端钉死策略不一致即返回
`reason=path_mismatch`，页面点亮“⚠ 节点齐套路径偏了”。未核验/核验中/已退回
均不得落库。

### API

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/policy` | 今日齐套策略 |
| POST | `/api/policy` | 选/钉策略（当天不可换弦，核验中不可改） |
| GET | `/api/flows` | 总览：待检/已过/待复核 + 策略名 |
| GET | `/api/flows/<id>` | 单流详情（含 `missing` 缺项卡片数据） |
| PATCH | `/api/flows/<id>/nodes` | 维护节点字段（改动后回到待检） |
| POST | `/api/flows/<id>/extract` | 抽取 |
| POST | `/api/flows/<id>/verify` | 节点齐套核验（`hold_ms` 可模拟核验窗口） |
| POST | `/api/flows/<id>/land` | 落库（body 可带 `path` 供路径校验） |
